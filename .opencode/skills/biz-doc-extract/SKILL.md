# Biz Doc Extract - 模块业务知识卡提取 Skill

本 skill 只做一件事：**针对一个模块，阅读真实源码，提取符合 `docs/FORMATS.md` 卡片契约的业务知识卡，写入 `.bizdoc/cards/<module>.md`。** 输出是"原始卡"，去重/合并/编号交下游 `biz-doc-synthesize`。

## 输入

调用方（subAgent）会提供：
- `inventory_path`：`.bizdoc/inventory.json`（由 `biz-doc-scan` 产出）
- `module`：本次要提取的模块名（如 `pricing`）
- `target_root`：代码根目录
- `workdir`：工作目录（= 项目根 `code-to-doc`）
- `output_path`：输出文件，约定 `.bizdoc/cards/<module>.md`

**下游必须通过文件交接**：调用方只传路径，subAgent 自己 Read。

## 执行步骤

### 1. 读取清单并锁定模块范围

1. Read `inventory_path`。
2. 过滤出 `module` 对应的 `classes[]` / `enums[]` / `public_methods[]` / `db_entities[]` / `http_endpoints[]` / `permission_annotations[]`。
3. 若该模块无任何条目，写一个仅含说明注释的空文件并结束（不要编造）。

### 2. 实读源码（关键，禁止仅凭清单臆断）

对本模块的每个类/枚举/方法对应的 `file:start_line-end_line`，用 Read **实际读取源码**。至少覆盖：
- 含业务计算/判定逻辑的方法体（if/switch/公式/阈值/常量）
- 状态枚举及其使用点（谁在改状态、允许哪些流转）
- 权限注解所在的方法与其守卫的资源
- 实体字段的约束注解与关系

清单只用来定位，**业务含义必须来自源码本身**。

### 3. 识别并产出知识卡（六类固定前缀）

按 `docs/FORMATS.md` §1.2 / §1.3 的**ID 前缀（固定）**产出卡片：

| 前缀 | 类型 | 何时产出 |
|---|---|---|
| `TERM-` | 术语 | 领域专有名词/黑话（如"账期""续订"），含代码命名与用户说法不一致者 |
| `ENT-` | 业务实体 | 有业务含义的核心对象及其关键关系/约束 |
| `BR-` | 业务规则 | 可判定的业务逻辑：条件→结果、阈值、计算公式、校验/BizException/拒绝分支 |
| `WF-` | 业务流程 | 多步骤、有参与者与顺序的业务过程（非技术调用链） |
| `SM-` | 状态机 | 有状态枚举 + 流转/触发条件 |
| `ROLE-` | 角色/权限 | 角色、权限点、资源可访问性 |

**卡内必填字段**（缺一不可）：`类型`、`同义词`、`模块`、`置信度`、`溯源`。

### 4. 卡片语法（严格照抄契约）

检索单元 = 一个 `## ` 二级标题块。格式：

````markdown
## BR-001 会员折扣计算

- **类型**: 业务规则
- **同义词**: 会员折扣, VIP优惠, 折扣率, member discount, discount rate
- **模块**: pricing
- **置信度**: 🟢 confirmed
- **溯源**: `src/main/java/com/example/pricing/DiscountService.java:42-58`

**规则**：当会员等级为黄金(GOLD)及以上时，订单金额享受 9 折；白金(PLATINUM)享 8.5 折。

**例外**：已是促销价的商品不参与叠加折扣。
````

要点：
- 标题行固定为 `## <ID> <中文标题>`。
- 五个 bullet 字段名固定为 `**类型**` / `**同义词**` / `**模块**` / `**置信度**` / `**溯源**`，顺序一致。
- 字段下方用加粗小标题（如 `**规则**：`）承载正文，可按类型自定义（规则用 `规则`/`例外`，流程用 `步骤`，状态机用 mermaid 块等）。
- 溯源格式：反引号包裹的 `相对路径:起行-止行`，多条用逗号分隔。

### 5. 置信度判定（硬规则）

- 🟢 `confirmed` — **有直接代码证据**，能指到 `file:line`。
- 🟡 `inferred` — 由命名/模式推断，未在代码中获得直接证据。
- 🔴 `gap` — 无法确定，需人工确认。

> **无溯源的条目不允许标记为 🟢。** 只从命名猜到的东西一律 🟡；完全无法判断的标 🔴 并在正文写明缺什么。

### 6. 同义词要求（检索命中的关键）

每张卡 `同义词` 必须包含「用户可能说出的词」，**中英文都要**：
- 中文口语说法（如 `会员折扣`、`打折`、`优惠`）
- 英文/代码说法（如 `member discount`、`discount rate`、`DiscountService`）
- 缩写/别名（如 `VIP`、`VIP优惠`）

只写代码里的类名不算达标——必须覆盖用户的自然语言问法。

### 7. 流程/状态机用 mermaid

流程与状态机的卡内嵌 mermaid 代码块（`flowchart` / `stateDiagram-v2`），节点引用真实枚举常量或步骤名，边的标签写触发条件。示例见 `docs/FORMATS.md` §1.3。

### 8. 编号与写出

- 卡 ID 在本文件内按前缀从 `001` 递增（`BR-001`、`BR-002`…）。**这是模块内临时编号**，最终全局唯一编号由 `biz-doc-synthesize` 统一分配/改写。
- 写文件前确保 `.bizdoc/cards/` 目录存在。
- 用 Write 写出 `output_path`，仅包含本模块的卡。

## 输出格式

- 文件：`.bizdoc/cards/<module>.md`
- 内容：若干 `## <ID> <标题>` 卡片块，符合 `docs/FORMATS.md` §1.2 / §1.3。
- 文件末尾可附 `<!-- module: <module> | cards: N | extracted_at: <ISO> -->` 注释（不参与卡片解析）。

## 约束

- **只读源码，不修改 `target_root` 下任何文件。**
- **引用优先**：每条 `溯源` 必须来自实际 Read 到的真实行号范围；`🟢` 必须带 `溯源`。
- **同义词必填**：中英双语，包含用户可能的说法；不满足则不能算达标卡。
- **不发明格式**：字段名、前缀、置信度三级措辞严格照 `docs/FORMATS.md`，不得自创指标名或字段名。
- 只处理被指派的一个 `module`，不同模块之间不要越界合并。
- 不写最终知识库文件（`docs/biz/**` 由 `biz-doc-synthesize` 负责）。
- 所有输出仅写入 `.bizdoc/cards/`。
