# 下一步优化计划

## 0. 现状（已实测）

| 基准 | 准确率 | 加权* | 说明 |
|---|---|---|---|
| 合成场景（读全代码） | **87.5%** | — | 覆盖完整时的上界 |
| Kill Bill v1（浅提取，2 模块） | 9.7% | ~19% | — |
| Kill Bill v2（深提取，5 模块/675 卡） | 29%–32% | ~45% | 深度杠杆 |
| Kill Bill v2 + 检索去重 | **41.9%** | **53.2%** | 检索杠杆 |

\* 加权 = (correct + 0.5×partial) / positive

机制层健康且稳定：**L0 引用 100% / L1 幻觉 0% / 忠实度 100% / 拒答 100%**。

**决定性诊断**：把每题 `expected_answer` 的关键事实拿去知识库里搜，与判分交叉——
**wrong & facts-absent = 0**，即**没有任何错题的答案是"库里查无此事实"**。
→ 瓶颈在**检索精度与作答完整性**，**不在**提取覆盖。

## 1. 已证明的两个杠杆

| 杠杆 | 动作 | 效果 |
|---|---|---|
| 提取深度 | 去掉"不必读每个文件"裁剪；2→5 模块；172→675 卡 | 9.7% → ~30% |
| **检索去重** | 同一张卡被 `modules/*.md` 与全局文件重复索引，k=5 实际只有 2~3 张唯一卡 → 按卡片身份去重 | ~30% → **41.9%** |

## 2. 剩余杠杆（按 ROI 排序）

### P0 — 便宜、直接
| # | 动作 | 为什么 | 预期 | 成本 |
|---|---|---|---|---|
| 1 | **k 调参**：k=5 → 8/10 | 5 张卡对跨卡问题不够 | +3~8pt | 1 次评测 |
| 2 | **根除 KB 内重复**：synthesize 产出的 `modules/<m>.md` 改为「模块概览 + 全局卡 ID 引用」，不再复制全文 | 去重只是检索期补救；**重复会让同一卡的 df 翻倍、idf 被压低，稀释相关卡得分**——这是打分层的隐性污染 | +2~5pt + 稳定性 | 改 synthesize skill，重跑合成 |
| 3 | **同义词检索（query expansion）** | KB 已有「同义词」字段；用户说"会员"、库里写 `Member`/`vipLvl`。建 synonym→card 倒排，查询时扩展 | +3~6pt | 改 `retrieval.py` |

### P1 — 中等成本
| # | 动作 | 预期 | 成本 |
|---|---|---|---|
| 4 | **LLM rerank**：BM25 召回 top-20 → LLM 重排 → top-5 | +5~10pt | 每题 +1 次调用 |
| 5 | **作答 prompt 强化**：要求"列全要点 + 标注来源卡 ID + 无据不得补" | +3~5pt（对 7 道 partial） | 改 `qa_eval.py`，重跑 |
| 6 | **黄金集扩容 + 消抖**：40 → 80 题（加难题/负样本）；每题 3 次判分取多数 | 指标可信度 | 中等 |

### P2 — 高成本
| # | 动作 | 何时启动 |
|---|---|---|
| 7 | **继续加深提取覆盖**（L2 13.7% → 40%+），按**子系统**拆分（invoice 再拆 calculator/generator/usage） | 仅当 P0/P1 做完仍 < 60% 时 |

## 3. 建议执行顺序（带验收门槛）

```
Step 1  k=10 + KB 去重根修        → 目标 ≥ 48%
Step 2  同义词检索                  → 目标 ≥ 52%
Step 3  LLM rerank + 作答 prompt    → 目标 ≥ 60%
Step 4  黄金集扩到 80 题 + 3 次判分  → 建立可信基线（消除 29%↔32% 抖动）
Step 5  若 < 70%，启动按子系统深提取，→ 目标 ≥ 75%
```

**每次改动前先跑一次基线**（同一套黄金集），改动后对比——避免"改完感觉变好了"。

## 4. 长期

- 把 L0/L1/L2/L4 接进 CI：改 prompt、改提取策略、换模型都自动回归。
- 迁移到自有老系统前，**先用合成场景验证每项改动**（那里 ground truth 完整、单次评测便宜），再上真实系统。
- 真实老系统落地时，**评测问题应逐步替换为真实用户问题**（Phase 2），届时 85% 目标才有真实意义。

## 5. 一个必须记住的结论

> 在真实大型遗留系统上，**"提取深度"决定上限，"检索质量"决定能否兑现上限**。
> Kill Bill 上真正拖后腿的不是没提取够，而是 **324 张卡被 100% 重复索引**这种廉价工程缺陷。
> 因此**优化顺序应是：先修检索/索引这类确定性问题，再加大提取投入**——本次 +12.9pt 就来自一处几行的修复。
