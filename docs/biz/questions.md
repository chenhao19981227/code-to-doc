# 待人工确认的问题 (questions)

本文件汇总消歧项、🟡 推断待验证项与 🔴 缺证据项。

## 一、消歧（同一概念在不同上下文含义不同）

1. **"状态"一词**：`OrderState` 是订单生命周期状态（有状态机，SM-001），而 `Member.status` 是会员启用/注销标志（0/1），二者不宜混用。请确认对外话术是否需统一命名。
2. **"金额"粒度**：`Order.goodsAmt`（商品折后净额）、`Quote.goodsNet`（试算商品净额）、`Order.paidAmt`（实付金额）、`Quote.payableAmt`（试算应付金额）在同一链路中含义相近但来源不同，请确认业务口径是否一致。

## 二、🟡 推断待验证

3. **BR-009 券与会员折扣是否叠加**：代码注释称「用券则牺牲会员折扣」，但实现中券抵扣基数是会员折后金额，未见回退会员折扣。请确认：用券时是否应回退（取消）会员折扣？当前实现是否存在缺陷？
4. **TERM-007 会员等级中文称谓**：代码仅有英文常量 `NORMAL/SILVER/GOLD/PLATINUM`，中文称谓（普通/银卡/金卡/白金）为推断，请确认官方称谓。

## 三、🔴 缺证据（详见 gaps.md）

5. **BR-011**：`Member.totalSpent` / `Member.lastOrderAt` 由谁、何时更新？
6. **BR-016**：`Order.paidAmt` 由谁、依据什么规则写入？
7. **BR-025**：`RefundController.create` 传入 `null` 订单，`orderId` 应如何在服务层解析出订单？
8. **WF-004**：退款审批（`approve`）之后，出款与 `finishRefund` 由谁触发？

## 四、其它待确认

9. **角色全集**：代码仅出现 `CS`、`CS_LEAD` 两个角色（方法级 `@PreAuthorize`）。是否存在其它角色、URL 级授权或未在本代码库中定义的权限点？系统无 Spring Security 配置类。
10. **支付超时的后续动作**：`OrderService.expired` 仅判定超时（BR-012），代码中未见超时后自动取消或释放库存的动作，是否有外部调度器负责？
11. **会员状态变更**：`Member.status`（1=启用/0=注销）的变更入口在代码中不存在，是否由外部系统维护？
12. **活动商品与券**：活动商品 `promoItem=true` 时会员折扣被置为无效（BR-018/BR-019 例外），但券仍可生效。请确认这是否为预期业务规则。
13. **`Coupon.expireAt` 为空**：当前实现将 `expireAt` 为空的券视为不可用（BR-006），请确认是否应视为"永不过期"。
